# はじめる

想定している公開コマンドは `npx vidro`、`npm exec vidro`、`pnpm dlx vidro`、`bunx vidro`、`yarn dlx vidro` です。いずれも、今日は公開パッケージをインストールしません。npm のパッケージ名は未決定で、`@vidro/cli` は private です。

## スキャフォールドとして存在するコマンド

CLI は次の名前を受け付けます。

```text
vidro init
vidro generate
vidro validate
vidro check
vidro show
```

どれも `@vidro/cli` に接続されていますが、現在は未実装である旨を書いてステータス 1 で終了します。動くセットアップ手順として扱わないでください。

## ソースファイル

プロジェクトは一つのファイルで宣言します。

```text
.vidro/<project>.vidro
```

`project` がそのファイルの名前です。ターゲットはディレクトリを、環境はそのディレクトリが受け取るファイルを表します。ファイル名の規則は[環境](/language/environments)にあります。これは設計上の意味です。スキャフォールドはまだファイルを生成しません。

## スキャフォールド

`vidro init` が実装されたら、検出、推論、質問の順に進みます。リポジトリのファイルを見る方が、質問より安いです。検査のあとも曖昧な事実、たとえば推論できないプロジェクト名だけを尋ねます。

ターゲット一覧、`PATH`、どの環境ファイルを取り込むか、空の値やシークレットの扱いをユーザーに尋ねてはいけません。それらは検出とコンパイラの方針です。
